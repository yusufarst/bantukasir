# 08 — Acceptance dan Definition of Done

Baseline P0–P11 — **39 suite Core, 0/39 FINAL PASS, semua NOT STARTED**. 28 Build Units baru di [11](11-BUILD-PLAN.md). Rebaseline documentation-only ini tidak mengklaim app tests, migration, restore, benchmark, browser/device atau pilot PASS.

## Bukti terarah versus final

BU provider COMPLETE berarti bounded artifact/evidence yang diuji sesuai scope; product suite belum FINAL PASS sampai semua consumer dan final points tersedia. Consumer memakai revision compatible yang lulus dan dibekukan. Tidak ada kredit dari fixture, prototype atau laporan executor.

33 suite integrated final di BU-VERIFY-002; DB01/REC01/REC02 di BU-VERIFY-001; DEVICE01 di BU-VERIFY-003; PERF01 di BU-VERIFY-004; RELEASE01 di BU-RELEASE-002 setelah actual authorized pilot. Bukti logika/HID/browser tidak menggantikan physical devices.

Evidence: NOT STARTED, BUKTI AWAL, PENDING, FAIL, FINAL PASS. Semua klausul wajib; missing consumer/unrun/failure menahan final. Catat revision/commands/target/dataset/results/reviewer/gap dan approval owner terpisah. Source/schema/assets/device/host changes setelah final proof memerlukan rerun affected checks. Technical PASS bukan deploy authorization. [CORE-MAP](requirements/CORE-MAP.md) memetakan setiap requirement.

## Metode verifikasi dan evidence wajib

- **Unit PHP/Pest atau PHPUnit dan TS/Vitest:** validation envelope/precision/bounds, half-up/residual, known/UNKNOWN transitions, MWA/replay determinism, payment arithmetic, period boundary, safe DTO/CSV dan state/recovery decisions. Test tidak boleh hanya meniru implementasi atau memakai fixture sebagai bukti race.
- **PostgreSQL nyata terisolasi:** uniqueness/partial constraints, ordered guards, same/different-key/source races, last-unit Sale/issue, open/close/refund/return/replay/lifecycle races dan failure injection setiap atomic boundary. Verifikasi sebelum/sesudah memakai source counts, ledger/balance/cost, snapshots, audit/result; mocks tidak membuktikan constraint/locking/rollback.
- **Targeted Playwright:** seluruh permitted dan denied route/object untuk Pemilik/Admin Operasional/Kasir; actual network payload/status/error/cache/export/media privacy; loading/empty/stale/UNKNOWN/rejected/UNCERTAIN/reload; complete draft→review→confirm→persisted result→history/report/document. Reuse suite bersama, kemudian lakukan final lintas consumer di BU-VERIFY-002.
- **Aksesibilitas/responsive:** 375/440/768/1024/1440px, zoom 200%, keyboard-only, focus order/visible/restoration, dialog Escape, input/scanner focus, ≥44px touch targets, reduced motion dan kontras menurut [DESIGN](../DESIGN.md). Long cart/table/form/error tidak memotong action atau menyembunyikan fakta penting; role-specific navigation/overlays tetap dapat dipakai.
- **Actual devices BU-VERIFY-003:** record USB/Bluetooth scanners, OS/browser/driver, printer/media/ukuran, source revision dan physical proof yang dapat diverifikasi Pemilik. Label harus terbaca dan benar-benar dapat discan; thermal/A4/reprint menghasilkan dokumen asli tanpa business mutation. Browser emulator atau print request tidak membuktikan hardware/tinta.
- **Operasi/recovery BU-VERIFY-001:** populated isolated final-schema migration dan backup/restore nyata dengan independent destination/key/media. Target database/host diverifikasi sebelum command; pertahankan original target. Rekonsiliasi seluruh fakta dan epoch/gap sesuai09 sebelum owner-approved reopening; tidak ada destructive production test/reset.

Seluruh permission/no-leak checks mencakup search, list/detail, history, status/recovery, validation errors, cache/browser storage, print/PDF/CSV/export/media/file URLs dan logs. Positive test Pemilik tidak menggantikan negative test dua staff role. Incoming write-only cost yang baru disubmit adalah input yang berizin; value tersebut tidak boleh keluar kembali sebagai DTO/error/history atau disimpan untuk client recovery. Authority tetap pada backend meskipun UI tidak ada.
