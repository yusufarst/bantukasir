### 10.2 The defect (F-7)

`config/database.php` gives `url => env('DB_URL')` to the runtime connection `pgsql` only, and the framework's URL parser lets a URL's host, port, database, user and password override the values given separately, so `phpunit.xml`'s `DB_DATABASE=bantukasir_test` did not hold for that connection once `DB_URL` was set. The harness checked the marker and the role of the migration connection only, which does not read `DB_URL`, and each observer copies the runtime connection's configuration. With a `DB_URL` to another database, the reset therefore passed while the tests' writes as the runtime role — `CacheTablesTest`'s among them — and the observers' reads went to that database, whose marker nobody read. The race workers already refused a connection whose marker is not `test`, but not a test database other than their test's.

Reproduced before the fix by the new regression test (section 10.4), at 16:03: with `DB_URL` pointing to the local database `bantukasir` of the same cluster, the runtime connection reached `bantukasir` (marker `local`) while the migration connection's marker check passed on `bantukasir_test`, and `TestDatabase::reset()` ran: "The operation ran". The local database received no write: the test makes none as the runtime role, and the reset wrote on the test database as the migration role.
